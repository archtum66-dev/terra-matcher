# NEAR Intents interface facts

Reference notes for settlement and quote code. Written from public documentation on 2026-10-29; the 1Click part was checked against the live API on 2026-11-07.

- Verifier contract: `intents.near`, Mainnet only, there is no testnet. Methods `execute_intents` and `simulate_intents`.
- `token_diff` intent: `{"intent":"token_diff","diff":{"<token id>":"<amount>", ...}}`. Token ids look like `nep141:wrap.near`. Amounts are decimal strings. Negative means give, positive means receive (no plus sign). Over all `token_diff` intents of one batch, every token must sum to zero, otherwise the whole batch fails.
- Signed message (NEP-413 standard): `payload.message` is a JSON string with `signer_id`, `deadline` (ISO 8601) and `intents`. Other standards (for example `raw_ed25519`) carry a JSON string with `signer_id`, `verifying_contract`, `deadline`, `nonce`, `intents`.
- Nonce (checked live 2026-11-07): 32 bytes, base64, **versioned nonce V1**: magic `5628f6c6` (4) | version `00` (1) | salt (4, from the view method `current_salt`) | nonce deadline in ns, little endian (8, not earlier than the intent deadline) | 15 random bytes. The earlier note "first 4 bytes are the salt" was wrong; such a nonce only passes as a legacy random nonce, which the verifier plans to drop.
- Signing (NEP-413, checked live): ed25519 over `sha256(u32le(2147484061) || borsh(message) || nonce || borsh("intents.near") || 0x00)`. Implicit accounts (64 hex characters of the public key) need no key registration; named accounts must call `add_public_key` on `intents.near` first.
- Protocol fee (checked live): view method `fee`, in pips (1_000_000 = 100 %); 1 pip on 2026-11-07. It is taken from every negative delta, so for a batch to balance each receiver gets `amount - ceil(amount * fee / 1_000_000)`. An exact zero-sum pair fails once the fee is above zero.
- `simulate_intents` (read-only view): with the format and signatures right but empty balances it panics `insufficient balance or overflow`; with a corrupted signature it panics `invalid signature`.
- Token ids on mainnet (from `GET https://1click.chaindefuser.com/v0/tokens`, 2026-11-07): wNEAR `nep141:wrap.near` (24 decimals), native USDC `nep141:17208628f84f5d6ad33f0da3bbbeb27ffcb398eac501a31bd6ad2011e36133a1` (6 decimals). `nep141:usdc.near` in the offline examples is a placeholder, not a mainnet token; `examples/mainnet/market.json` uses the real ids.
- 1Click quote: `POST https://1click.chaindefuser.com/v0/quote`. Required request fields: `dry`, `swapType` (`EXACT_INPUT`, `EXACT_OUTPUT`, `FLEX_INPUT`), `slippageTolerance` (basis points), `originAsset`, `depositType` (`ORIGIN_CHAIN`, `INTENTS`), `destinationAsset`, `amount` (string, smallest unit), `refundTo`, `refundType` (`ORIGIN_CHAIN`, `INTENTS`), `recipient`, `recipientType` (`DESTINATION_CHAIN`, `INTENTS`), `deadline` (ISO 8601). Optional: `depositMode`, `referral`, `quoteWaitingTimeMs`, `appFees`. With `dry: true` the answer has no `depositAddress` and no `deadline` in the quote.
- Quote answer (checked live 2026-11-07): HTTP **201**. `correlationId`, `timestamp`, `signature` (`ed25519:...`), `quoteRequest` (echoed, with defaults filled in: `depositMode` `SIMPLE`, `confidentiality`, `insured`, `appFees`), `quote` with `amountIn`, `minAmountIn`, `amountOut`, `minAmountOut`, `timeEstimate` (seconds) plus `amountInFormatted`, `amountInUsd`, `amountOutFormatted`, `amountOutUsd`, `refundFee`, `withdrawFee`. Unknown fields are ignored by the parser.
- Authentication: header `X-API-Key` (preferred) or `Authorization: Bearer <JWT>`. Not required for dry quotes: without a key the echoed request carries a default app fee of 20 basis points. Errors: 400 invalid input, 401 invalid key.
- Still unverified against the live system, marked `UNVERIFIED` in code: the `raw_ed25519` payload. Not done at all: a real `execute_intents` (needs deposited tokens).
